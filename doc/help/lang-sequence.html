State machines

SEQUENCE state_field {
    PRESENT state
        NEXT state;                         (unconditional)
      or
        IF expression NEXT state [OUT outputs];
        ...
        DEFAULT NEXT state [OUT outputs];
        [OUT outputs;]                      (in this state)
        [IF expression OUT outputs;]        (in this state, when true)
    PRESENT state
        ...
}

A SEQUENCE block describes a synchronous state machine. The state register is a field of registered outputs or nodes; each PRESENT names one value of the field and says which state follows at the next clock and which outputs are active. cupl turns the block into the equations of the state register and the outputs.

Kinds of flip-flops

KeywordState register made of
SEQUENCEthe device's default register type (D flip-flops in GALs and the 22V10)

SEQUENCEJKJK flip-flops (.j, .k)
SEQUENCERSSR flip-flops (.s, .r)
SEQUENCETT flip-flops (.t)

The device must have the chosen kind; the virtual device has all of them (see flipflops.pld on the extensions page).

Example

A traffic light in a GAL22V10. The states have names made with $define, which keeps the encoding in one place:

Pin 1  = clk;
Pin 2  = car;              /* car waiting on the side road */
Pin 3  = rst;              /* asynchronous reset to MAIN_GO */

Pin [14..15] = [s1..0];    /* state register */
Pin 16 = main_red;
Pin 17 = main_yellow;
Pin 18 = main_green;
Pin 19 = side_red;
Pin 20 = side_green;
Pin 21 = walk_req;         /* registered output */

field state = [s1..0];

$define MAIN_GO    'b'00
$define MAIN_STOP  'b'01
$define SIDE_GO    'b'11
$define SIDE_STOP  'b'10

sequenced state {
    present MAIN_GO
        if car  next MAIN_STOP;
        default next MAIN_GO;
        out [main_green, side_red];
    present MAIN_STOP
        next SIDE_GO;
        out [main_yellow, side_red];
    present SIDE_GO
        if car  next SIDE_GO   out walk_req.d;
        if !car next SIDE_STOP;
        out [main_red, side_green];
    present SIDE_STOP
        next MAIN_GO;
        out [main_red, side_red];
}

state.ar = rst;
walk_req.ar = rst;

PRESENT and NEXT

PRESENT value starts the description of one state. NEXT value alone means that the machine always goes to that state at the next clock. Otherwise each IF expression NEXT value gives a transition taken when the expression is true, and DEFAULT NEXT the one taken when none of them is true. The conditions of one state should not overlap. A state that no PRESENT describes and that has no way out should not be reachable: make sure the reset (state.ar) or the encoding keeps the machine in the listed states.

Outputs

Written asThe output is
OUT list; after PRESENTcombinational: true while the machine is in this state.
IF expr OUT list;combinational: true while in this state and the expression is true.
IF expr NEXT s OUT list;
DEFAULT NEXT s OUT list;		registered: set at the clock that makes this transition, so it is true in the next state. An extension such as walk_req.d may name the register input.

A state may have only one unconditional OUT statement; list all its outputs in it (out [main_green, side_red];). Two of them give multiple unconditional statements for state. An output is false in every state that does not name it.

Hints

  • A state machine can be built by a macro; the sequence keyword may be a macro parameter.
  • The simulator shows the state register as a field; put it into ORDER to follow the states.
  • Gray-code encodings (as above) let only one register bit change per transition.
