Test vector files (.si)

A .si file has a header, an ORDER statement that says which signals the columns of the vectors are, and the vectors after VECTORS:. Comments are written /* ... */ as in the design. Lines may end in LF or in CR LF.

The original csim misreads loops ($FOR, $REPEAT, $WHILE, $UNTIL) in a file whose lines end in LF alone, for example loop index variable already in use; give test files that are also run with it CR LF line ends.

Name     Decoder;
PartNo   HELP03;
Date     2026-01-01;
Revision 01;
Designer LinCUPL Help;
Company  LinCUPL;
Assembly None;
Location None;
Device   g16v8a;

ORDER: iorq, %1, addr, %2, rom_cs, ram_cs, io_cs, %2,
       page0, all_ones, any_set, parity, low_nibble_5;

BASE: hex;

VECTORS:
0 '00'  HLL  HLLLL
0 '3F'  HLL  LLHHL
0 '40'  LHL  LLLLL
0 'B5'  LHL  LLHLH
0 'C0'  LLL  LLLLL
1 'F5'  LLH  LLHLH
1 'FF'  LLH  LHHHL
1 '7F'  LLL  LLHHL

Header

The header has the same items as the header of the design. csim compares them with the compiled design and gives the note inconsistent header information when they differ, so that test vectors are not used with the wrong design by mistake.

ORDER

ORDER: item, item, ... ;

The items are pin and node names, fields, %n for n blanks in the listing, and texts in double quotes that are printed as they are. The statement may span several lines. Each signal takes one column in the vectors; a field takes one quoted value (see below). Blanks between the values of a vector are ignored, so they can be grouped freely.

ORDER: clk, " en=", en, clr, %2, cnt, top;

The fields of the design (FIELD statements) are known to the simulator. A .si file may define further fields of its own with a FIELD statement before ORDER:

FIELD lo = [c1..0];
ORDER: clk, en, clr, %1, cnt, %1, lo, top;

Signal values and polarity

Values refer to the logical signal, as in the design. For a pin declared active low (Pin 16 = !y_nor;) the vector gives H when y_nor is true, which is a low level on the pin:

ORDER: a, b, %4, y_and, y_or, y_xor, y_nand, y_nor;

VECTORS:
0 0    L L L H L
0 1    L H H H H
1 0    L H H H H
1 1    H H L L H

BASE

BASE: hex | decimal | octal | binary;

The base of the field values in quotes; the default is hexadecimal.

VECTORS

After VECTORS: each line is one test vector, with one value per signal of ORDER:

ValueForMeaning
0, 1inputsDrive the input low or high.
Cclock inputsA clock pulse 0-1-0: the registers clocked by this input load at its rising edge.
Kclock inputsAn inverted pulse 1-0-1.
RinputsA random 0 or 1.
Pclock inputPreload: the registers are set to the values given for the outputs in this vector (0, 1, or a field value in single quotes).
L, HoutputsExpect the output low or high.
ZoutputsExpect the output disabled (high impedance).
Xinputs, outputsUndefined input; for an output, expect an undefined value.
NoutputsDo not check the output.
*outputsDo not check; the listing shows the simulated value.

A register may be clocked by another signal of the design, for example by the register before it in a ripple counter (q1.ck = q0;). It loads when that signal rises while the vector is simulated.

The original's simulator for the virtual device and the ATF150x CPLDs never clocks such a register; the usual workaround was to pass the clock through a PINNODE. LinCUPL does not need it.

A field takes its value in quotes: '5A' in single quotes sets inputs, "5A" in double quotes gives the expected value of outputs, in the base of the file. A quoted value may also be "*", "X" or "Z" for all bits.

$MSG "Reset, then count from 0";
0 0 1 0 1  "0" L
C 1 0 0 1  "1" L
C 1 0 0 1  "2" L

An output is checked after the inputs have been applied and, for a C vector, after the clock pulse. The directives between the vectors repeat vectors, print messages and control the run.

Preload

A P in the clock column loads the registers directly, without going through their logic; useful to start a test in a particular state:

ORDER: clk, en, clr, %1, cnt, top;
VECTORS:
P 0 0 '5' X          /* registers := 101 */
0 0 0 "5" L
C 1 0 "6" L

With the virtual device a preload sets active-high registers to the complement of the given values.

For an ATF150x JEDEC map, preload values are physical storage levels: 0 loads zero, 1 loads one, and X makes the register unknown. Signal-name polarity does not invert these values. Each bonded macrocell is addressed by its physical pin, including a register used for internal feedback. Omitted registers and columns with N or * keep their state. Loading bypasses clocks and asynchronous controls, and establishes clock history after all loads. This initializes simulator state; it does not simulate the device's electrical preload or JTAG programming protocol.
