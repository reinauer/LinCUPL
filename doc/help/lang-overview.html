Design file structure

A CUPL design (.pld file) is plain text. It starts with a header, declares the pins, and then describes the logic with equations, tables and state machines. Line breaks and blanks do not matter; every statement ends with a semicolon.

Name     Counter;
PartNo   HELP02;
Date     2026-01-01;
Revision 01;
Designer LinCUPL Help;
Company  LinCUPL;
Assembly None;
Location None;
Device   g22v10;

/* 4-bit binary counter with count enable, asynchronous reset,
   synchronous preset to 1111 and three-state outputs */

Pin 1  = clk;           /* clock of all registers */
Pin 2  = en;            /* count when high */
Pin 3  = rst;           /* asynchronous reset to 0000 */
Pin 4  = pre;           /* synchronous preset to 1111 */
Pin 13 = !oe;           /* outputs enabled when the pin is low */

Pin [14..17] = [q0..3];
Pin 18 = carry;

field count = [q3..0];

/* Toggle a bit when all lower bits are 1 */
q0.d = q0 $ en;
q1.d = q1 $ (en & q0);
q2.d = q2 $ (en & q0 & q1);
q3.d = q3 $ (en & q0 & q1 & q2);

count.ar = rst;
count.sp = pre;
count.oe = oe;

carry = en & count:'h'F;

Header

The header describes the design. Each item is a keyword, a text and a semicolon:

ItemMeaning
NameName of the design. The JEDEC file is named after it (see -n).
PartnoPart number.
Revision or RevRevision.
DateDate.
DesignerDesigner.
CompanyCompany.
Assembly or AssyAssembly the device goes into.
Location or LocPosition on the board.
DeviceThe device to compile for, e.g. g22v10; a device given to cupl on the command line takes precedence. virtual compiles device independently.
FormatDownload formats to write in addition to the command line options: j (JEDEC), h (ASCII-hex), i (HL).

A missing item gives the note missing header item(s); the design still compiles. The texts appear in the documentation and JEDEC files, and the simulator compares the header of the .si file with them.

Comments

A comment starts with /* and ends with */. It may span several lines and may stand anywhere a blank may. // starts a comment that runs to the end of the line; the file must end with a line break after it.

A source line may be at most 255 characters long (line exceeds maximum length).

Names

Names of pins, nodes, fields and other variables consist of letters, digits and the underscore. Upper and lower case are different: A0 and a0 are two signals. Keywords (PIN, field, Sequenced, ...) may be written in any case. A name that ends in a number, such as q3 or addr12, is an indexed name and can be used in ranges like [q0..3].

Numbers

Pin and node numbers are decimal. All other numbers are hexadecimal unless a base prefix in single quotes says otherwise:

PrefixBaseExamples
'b'binary'b'1010, 'b'1X0X
'o'octal'o'17
'd'decimal'd'200
'h'hexadecimal'h'3F, 'h'8X, 3F

The prefix letter may be upper or lower case. In binary, octal and hexadecimal numbers an X is a don't-care digit (one, three or four bits): addr:'h'8X is true for every address from 80 to 8F.

Because the default base is hexadecimal, 10 means sixteen. Write 'd'10 for ten.

Reserved words

These words are keywords in any case and cannot be used as names:

APPEND    ASSEMBLY  ASSY      COMPANY   CONDITION DATE      DECLARE
DEFAULT   DEMORGAN  DESIGNER  DEVICE    EXIT      EXTERN    FIELD
FLD       FORMAT    FUNCTION  GLOBAL    GROUP     GRP       IF
INIT_TO   LOC       LOCATION  MIN       MSG       NAME      NEXT
NODE      OUT       PARTNO    PIN       PINNODE   PRESENT   PROPERTY
REGISTER_SELECT     REV       REVISION  SEQUENCE  SEQUENCED SEQUENCEJK
SEQUENCERS          SEQUENCET TABLE     TROFF     TRON

The single letters b, d, h and o are reserved for the base prefixes of numbers.
