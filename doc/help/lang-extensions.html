Pin extensions

An extension after a pin or node name selects one part of the macrocell behind it: the D input of its flip-flop, its output enable, its reset, and so on. An equation without an extension describes a combinational output.

q0.d = q0 $ en;
q1.d = q1 $ (en & q0);
q2.d = q2 $ (en & q0 & q1);
q3.d = q3 $ (en & q0 & q1 & q2);
...
count.ar = rst;
count.sp = pre;
count.oe = oe;

An extension may follow a field or a list: count.ar = rst; sets the reset of every bit. On the right side of an equation, q0 is the output of the flip-flop and an extension selects another feedback path (q.io, q.dfb) where the device has one.

Common extensions

ExtensionMeaning
.dD input of a D flip-flop: the output takes this value at the clock.
.tT input of a toggle flip-flop: the output changes at the clock when it is 1.
.j, .kJ and K inputs of a JK flip-flop.
.s, .rSet and reset inputs of an SR flip-flop. Both 1 at a clock gives an undefined state.
.l, .leData input and enable of a latch: the output follows .l while .le is 1 and holds when it is 0.
.ckClock of the flip-flop, where the device allows a clock other than the clock pin (CPLDs, ATF750, the virtual device).
.ceClock enable: the flip-flop loads only while it is 1.
.arAsynchronous reset: the output goes to 0 at once, without a clock.
.apAsynchronous preset: the output goes to 1 at once.
.srSynchronous reset: the output goes to 0 at the next clock.
.spSynchronous preset: the output goes to 1 at the next clock.
.oeOutput enable: the pin drives its value while the expression is 1 and is high impedance (Z in the simulator) when it is 0. Without an .oe equation the output is always enabled.
.ioOn the right side: the level at the pin, for devices that can feed back either the pin or the register.
.dfb, .tfbOn the right side: the output of the D or T register, where the macrocell can feed it back separately from the pin.
.dq, .lqOutput of an input register or input latch (registered input pins of CPLDs).
.oemux, .ckmuxSelect a global output enable or global clock instead of a product term.

Other extensions exist for particular architectures (for example .iod, .iol, .iock and .ioar for the registers in the I/O cells of the ATF150x). The data sheet of the device describes these parts of the macrocell.

Which extensions a device has

Each device supports only the extensions of its macrocells:

DeviceExtensions
g16v8a, g20v8a.oe .d
g22v10.oe .d .ar .sp
v750c.d .t .ar .ck .ckmux .oe .sp .dfb .tfb .io
v2500c.d .t .ar .ck .oe .sp .io .ce .dfb
f1502plcc44.d .t .s .r .oe .oemux .ck .ckmux .ar .dq .lq .io .iod .iol .iock .ioar
virtualall of them

The list for any device is shown by cbld:

cbld -eu Atmel.dl g22v10

An extension the device does not have gives unknown extension and invalid usage. On a GAL22V10 all flip-flops share the clock pin and one product term each for .ar and .sp: the reset and preset act on every registered output, and two different .ar expressions fail with excessive number of product terms. Outputs without an .ar or .sp equation get the note no expression assigned, which is harmless.

Flip-flop types

The virtual device has every kind of flip-flop. This design builds the same counter from D, JK, SR and T flip-flops with the state machine statements; each of them writes the matching extensions:

$MACRO counter kind name
kind name {
    present 0  if up next 1;  default next 3;
    present 1  if up next 2;  default next 0;
    present 2  if up next 3;  default next 1;
    present 3  if up next 0;  default next 2;
}
$MEND

counter(sequenced,  dcount);
counter(sequencejk, jcount);
counter(sequencers, rcount);
counter(sequencet,  tcount);

[d1..0, j1..0, r1..0, t1..0].ck = clk;

Converting flip-flop types

REGISTER_SELECT output = n; has cupl rewrite the flip-flop equations of an output for another flip-flop type, so a design written for one type fits a device that has another:

nConverts to
1D (.d)
2T (.t)
3JK (.j, .k)
4SR (.s, .r)

The output may be a list, as in REGISTER_SELECT [y0..2] = 2;. When the device lacks the flip-flop type, cupl warns and leaves the equations as they are. For example, q.s = s; q.r = r; with REGISTER_SELECT q = 1; becomes q.d = s # !r & q;.

The original keeps only one input of an SR or JK flip-flop when it converts SR to D, SR to T or JK to T: the terms of the other input are lost, and csim stops with sr initialization on a converted SR flip-flop; and with DEMORGAN level 2 on the output it stops with symbol table corrupted. LinCUPL converts both inputs, with or without DEMORGAN.
