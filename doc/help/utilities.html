backpin: writing pin numbers into the design

backpin [-p] [-f] [-b backup] [-l logfile] [-u library] device design.pld

When a fitter has chosen the pins of a design, backpin writes the chosen numbers into the PIN and PINNODE statements of the design, so that the next compile keeps them. backpin -f does the opposite: it removes the numbers, so that the fitter places every signal anew.

OptionMeaning
(none)Write pin and node numbers.
-pWrite pin numbers only; the PINNODE statements lose their numbers.
-fFloat: remove all pin and node numbers.
-b fileName of the backup copy (default design.bak); it may not be the design itself.
-l fileWrite the messages to a log file.
-u libraryDevice library.

backpin reads the placements from design.plc, a list of lines like PIN 21 = y ; and NODE 615 = r ;. It first copies the design to the backup file and then writes the new design from that copy.

backpin -u Atmel.dl f1502plcc44 bp.pld   # Pin = y;  becomes  Pin 21 = y;
backpin -f f1502plcc44 bp.pld            # Pin 21 = y;  becomes  Pin   = y;

backpin rewrites PIN and PINNODE statements with one signal, a range or a list (Pin = y;, Pin = [q0..3];, Pin = [a, !b];, Pinnode [601, 602] = [r, s];); blanks, comments and line breaks inside the brackets stay as written. A list gets its numbers in brackets on the left, Pin [4,5] = [a, !b];; when one of its signals has no placed pin (and with -f, or -p for PINNODE) the list is written without numbers. NODE statements carry no numbers and are copied as they are.

backpin writes the design only when it has read all of it: at a statement it cannot read (a missing semicolon, for example) it stops with a message and leaves the design unchanged.

The original backpin stops at NODE statements and at lists with blanks or ! between the names, and the design it writes then ends there, with the rest only in the .bak copy; for lists without placed pins it writes pin number 0. It also ignores the name given with -b, reads the device and the design only from a command line with at least one option (backpin f1502plcc44 bp.pld looks for a design called &), and prints a meaningless line number with invalid flag.

In LinCUPL

The Utilities menu runs backpin on the open design (or the project) with its device and the device library:

Menu entrybackpin run
Float All Pins and Nodesbackpin -f
Assign Pins and Pinnodesbackpin
Assign Pins Onlybackpin -p
Backpin...a dialog with all options and the command line

The ATF150x fitters report their placement in the .pin file; LinCUPL converts it into the .plc file backpin reads, and warns when the placement is older than the design. The editor receives the new text as a single change, so Edit > Undo brings the old pin numbers back. Should a backpin program write only part of the design, LinCUPL puts the design back as it was and says why, instead of loading the shortened file.

cbld: device library contents

cbld [-flags] [library] [devices]
FlagLists
-tthe names of all devices in the library
-lfor each device: revision, pins, fuses and product terms
-ethe extensions each device supports
-uuse the library named on the command line
-bbuild a library from a build file
cbld -tu Atmel.dl
cbld -lu Atmel.dl g22v10 v750c
cbld -eu Atmel.dl f1502plcc44

The output of cbld -lu Atmel.dl g22v10:

Device        Rev   Pins  Fuses  Pterms
------------  ---   ----  -----  ------
g22v10         01    24    5892    132

Utilities > Device Library Table of Contents (cbld -t) shows the device list of the current library, and the device browser runs cbld -l and -e for the selected device.
