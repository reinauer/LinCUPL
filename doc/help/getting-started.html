Getting started

The LinCUPL window

  • The editor in the middle has one tab per open file: designs (.pld), test vectors (.si) and the files the tools write. CUPL keywords, pin extensions, numbers and comments are coloured.
  • Design & Output Files (left) lists the files that belong to the design in the current tab: the source, its test vectors and every output file, with their state. Double-click one to open it.
  • Diagnostics & Build Output (bottom) shows the errors and warnings of the last run, an explanation of the selected message and the complete output of the tools. Clicking a message jumps to its line.
  • The status bar shows the open project, the device of the design, the device library in use and the cursor position.

A first design

Choose File > New Project (Ctrl+N) to have the header and the pin declarations written for you, File > New Empty PLD for a blank design, or File > Open for an existing one. A design is a text file: a header naming the design and the device, pin declarations and equations. This one puts five gates into a GAL16V8:

Name     Gates;
PartNo   HELP01;
Date     2026-01-01;
Revision 01;
Designer LinCUPL Help;
Company  LinCUPL;
Assembly None;
Location None;
Device   g16v8a;

/* Basic gates in a GAL16V8 */

/* Inputs */
Pin 2 = a;
Pin 3 = b;

/* Outputs */
Pin 12 = y_and;
Pin 13 = y_or;
Pin 14 = y_xor;
Pin 15 = y_nand;
Pin 16 = !y_nor;     /* active low: the pin is low when a or b is high */

y_and  = a & b;
y_or   = a # b;
y_xor  = a $ b;
y_nand = !(a & b);
y_nor  = a # b;

& is AND, # is OR, $ is exclusive OR and ! is NOT (see Expressions). Options > Devices lists the devices of the library and writes the chosen name into the Device line.

Compiling

Run > Device Dependent Compile (F9) saves the design and runs cupl for the device named in the file. The compiler options decide which output files are written; by default these are the JEDEC file (.jed) for the device programmer, the listing (.lst), the documentation file (.doc) and the absolute file (.abs) that the simulator needs. They open as tabs next to the source and are reloaded after every run.

Run > Device Independent Compile (Shift+F9) compiles for the virtual device, which checks and simulates the logic before a device is chosen.

When a run fails, the Diagnostics list shows each message with its line. The explanation beside it comes from the catalog of error messages.

Simulating

Test vectors go into a .si file with the same name as the design. File > New Simulation (.SI) starts one from the pins of the open design. Each line of vectors sets the inputs and states the outputs it expects:

ORDER: a, b, %4, y_and, y_or, y_xor, y_nand, y_nor;

VECTORS:
0 0    L L L H L
0 1    L H H H H
1 0    L H H H H
1 1    H H L L H

Run > Device Dependent Simulate (F10) runs csim; Compile & Simulate (F11) does both. The simulation listing (.so) shows every vector and marks each output that differs from the expected value. See the simulator and test vector files.

Waveforms

Run > Launch Waveform Simulator (F12) opens the test vectors of the design in LinSim, which shows them as waveforms, lets you edit them and runs the simulator.

Projects

A project is a design: its .pld file together with its .si file and output files. There is no separate project file. File > New Project creates a design with the wizard and opens it as the project, File > Open Project (Ctrl+Shift+O) opens an existing design as the project, and File > Close Project closes its tabs. While a project is open, compiling, simulating, the file list and the utilities work on the project's design whichever tab is active; if the active tab holds another design, LinCUPL asks which one to compile. A device chosen as override in Options > Devices is kept with the project. Options > Reopen Last Project at Startup opens the last project again when LinCUPL starts.

Device library, paths and fonts

Options > Environment & Tool Paths chooses the device library (Atmel.dl or cupl.dl) and, if the command line tools are not next to LinCUPL, the directory they are in. Options > Font sets the fonts of the editor (source and output tabs), the messages (diagnostics and build log) and the sidebar. The Utilities menu runs backpin to float or assign the pins of a fitted design, and lists the contents of the device library with cbld.

Tools menu

Tools > Add Tool adds an external program to the Tools menu, for example the software of a device programmer; up to 13 tools can be defined and changed with Tools > Edit Tools. Each tool has a menu name, the command, its arguments and a working directory (by default the design's). In these, placeholders are replaced when the tool runs:

PlaceholderReplaced by
$(FILE)the file of the active tab
$(DESIGN)the project's (or active) design file
$(DIR)the directory of the design
$(NAME)the design's name without extension
$(DEVICE)the device (the override, else the design's Device)
$(JED)the design's JEDEC file
$(SI)the design's .si file
$(LIB)the device library

Arguments are split like a shell command line, so a placeholder whose value contains blanks stays one argument; quotes group words. A tool can save all modified files first, show its output in the build log (where Tools > Stop Running Tool, Ctrl+Shift+F9, ends it) or start in a window of its own, and can have a button on the user tools toolbar.

Command:    minipro
Arguments:  -p ATF22V10C -w $(JED)

From the command line

Everything LinCUPL does can be done in a terminal:

cupl -jaxl gates.pld      # compile: .jed, .abs, .doc, .lst
csim -l gates             # simulate gates.si: .so

See also: Compiler options, Simulator.
