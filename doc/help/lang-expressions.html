Expressions, lists and fields

Logic operators

OperatorMeaningPrecedence
!NOT1 (binds tightest)
&AND2
#OR3
$exclusive OR4

Operators of higher precedence are applied first, and parentheses change the order: a # b & c is a # (b & c), and a # b $ c is (a # b) $ c. The constants are written 'b'0 and 'b'1; a bare 1 on the right side of an equation is a syntax error.

y_and  = a & b;
y_or   = a # b;
y_xor  = a $ b;
y_nand = !(a & b);
y_nor  = a # b;

cupl expands every expression into a sum of products (an OR of AND terms) and then minimizes it. An exclusive OR of many signals needs many product terms; the excessive number of product terms error says that an output needs more terms than its macrocell has.

Lists

Square brackets group signals into a list: [a, b, c]. A range of indexed names, [a7..0], is [a7, a6, ..., a0], and lists and ranges may be mixed: [q0..3, carry]. The first element is the most significant bit when the list is compared with a number.

An operator between two lists of the same length works on each pair of elements; between a list and a single signal it works on each element with that signal:

[y1..0] = [a1..0] & [b1..0];   is   y1 = a1 & b1;  y0 = a0 & b0;
[y1..0] = [a1..0] & en;        is   y1 = a1 & en;  y0 = a0 & en;

FIELD

FIELD name = [list];

A FIELD names a list so that it can be used like a number: in equations, in tables, as the state register of a state machine and in the simulator. A field may contain another field.

field addr = [a7..0];

A field (or a list) can stand anywhere a list can, and an extension applies to every element: count.ar = rst;

Comparing with values

field:value is true when the bits of the field match the number. The number is hexadecimal unless it has a base prefix, and X digits match anything. field:[low..high] is true for every value in the range:

rom_cs = !iorq & addr:[00..3F];         /* 'h'00 to 'h'3F */
ram_cs = !iorq & addr:[40..BF];
io_cs  =  iorq & addr:'b'1111XXXX;      /* F0 to FF: low four bits ignored */

page0        = addr:0;                  /* all address bits low */
...
low_nibble_5 = [a3..0]:'d'5;

A range is turned into as few product terms as possible, so ranges that start and end on powers of two are cheapest.

Several single values are listed with commas: [a3..0]:[3, 7] is true for 3 and for 7, and several ranges as well: [a3..0]:[0..1, 4..5]. Ranges and single values can be mixed in any order; the list is true for each of them: f:[0..3, 7] and f:[7, 0..3] are both true for 0 to 3 and for 7, as f:[0..3] # f:7 is. The same holds for the input lists of a TABLE.

The original CUPL computes such lists wrongly: a single value after a range takes on the bits that the range leaves open (f:[0..3, 7] is true for 0 to 7), and a range after a single value is a syntax error. Write f:[0..3] # f:7 in designs that are also compiled with it.

Bit field operators

ExpressionValue
field:&AND of all bits: true when every bit is 1.
field:#OR of all bits: true when any bit is 1.
field:$Exclusive OR of all bits: true when an odd number of bits is 1.
all_ones     = addr:&;                  /* AND of all bits */
any_set      = [a3..0]:#;               /* OR of the low four bits */
parity       = [a2..0]:$;               /* XOR of the low three bits */

Comparing two fields

list == list is true when both lists have the same value, bit by bit:

match = (count == compare) & !count_is_zero;

An 8-bit comparison needs many product terms; it suits a CPLD better than a GAL.

Arithmetic

CUPL has no addition or comparison by magnitude in equations. A counter is written with exclusive ORs (counter.pld), with toggle flip-flops (cpld.pld) or as a state machine; an adder with a FUNCTION. Arithmetic on numbers is available in the macro language, which computes values while the design is read.
