Compiler options

The cupl command

cupl [-flags] [-u library] [device] design.pld

Flags may be given separately (-j -a -l) or together (-jal). A device on the command line is used instead of the Device line of the design; virtual compiles device independently. -u names the device library; without it cupl uses the library of the environment (LIBCUPL) or the default library. Without any output flag cupl reads and checks the design and writes nothing.

cupl -jaxl counter.pld              # JEDEC, absolute, documentation, listing
cupl -u cupl.dl -jl p22v10 counter.pld
cupl -axl virtual counter.pld

The usage text that cupl prints describes several flags wrongly (-g "create Gates file", -z "deactivate unused OR gates", -q "subtle warnings off", ...). The tables below say what each flag does.

Output files

FlagEffect
-jJEDEC fuse file (.jed), named after the Name field of the header. For an ATF150x and other devices placed by a fitter cupl writes the fitter input (.tt2, .pla) and runs the fitter, which writes the .jed. PROMs get a note instead (they use -h).
-nName the JEDEC and ASCII-hex files after the design file instead (counter.pld gives counter.jed).
-aAbsolute file for the simulator (.abs) and its readable form (.sim).
-lListing with line numbers and messages (.lst).
-xDocumentation file (.doc) with the expanded and minimized equations and the symbol table.
-fAdds the fuse plot and the chip diagram of the device to the .doc file, and writes that file even without -x. Devices placed by a fitter get neither.
-bBerkeley PLA file (.pla; for fitter devices also the .tt2).
-cPALASM source (.pds); devices PALASM does not know get a warning, the file is written anyway.
-eThe design after macro expansion (.mx).
-pPDIF netlist (.pdf).
-tEDIF netlist (.edf).
-hASCII-hex download file (.hex) for PROMs; other devices get the note "invalid download format" in the listing.
-iHL download file (.hl) for the Signetics IFL devices (e.g. f153); other devices get the same note.
-gProgram the security fuse: the JEDEC file gets G1 instead of G0, and a programmed device cannot be read back or verified. For fitter devices cupl only writes PROPERTY CUPL SECURITY = ON into the .tt2, which the ATF150x fitters ignore; they take PROPERTY ATMEL {SECURITY = ON}.
-dIFL devices: the OR-array connections of unused product terms are switched off (the .jed changes). No effect on other devices.
-zq, -zx-zq writes the PLA fitter input and runs the fitter, like -j for fitter devices. -zx asks for an XNF netlist, which cupl does not write: it needs the external program pla2xnf, and devices other than ga... get a note. -z alone prints the usage and stops.

Logic options

FlagEffect
-m0 ... -m4Minimization: none, quick (default), Quine-McCluskey, Presto, Espresso. -m alone is -m1.
-kbChoose the polarity of each pin and node that needs fewer product terms; overrides DEMORGAN statements.
-kdApply DeMorgan to all pins and nodes; overrides DEMORGAN statements. With both -kb and -kd the one given last counts.
-ksMinimize all outputs together so that they can share product terms. Changes the result with -m2 ... -m4; with -m1 it has no effect.
-kxKeep XOR equations as XOR, for the virtual device and fitters with XOR gates.
-oOne-hot state machines: the state numbers of SEQUENCE blocks are one-hot codes (1, 2, 4, ...) and each state is recognised by its own bit. Designs written for binary state numbers usually no longer compile.
-rNever share product terms between outputs, not even the single AR and SP terms of a 22V10; such designs then fail with "excessive number of product terms".

Other flags

FlagEffect
-sRun csim on the design's .si file after a successful compile. It writes .abs, .sim, .so and .wo, and with -j adds the test vectors to the .jed. Without a .si file the run fails.
-wThe same as -s (the usage text calls it "warnings off"; it is not).
-qMessages in the form design.pld(6) : Error [0037ca] :... instead of the source line with a caret; also writes a .lst file. It does not switch off any warning.
-y1 ... -y8Accepted and ignored.
-u libraryDevice library.

Best polarity and DeMorgan exclude each other, and so do Product-term sharing and Never share product terms: checking one clears the other.

Device Independent Compile passes virtual as the device and always adds -a -l -x; it leaves out -g, -d, -n, the download flags and -f, which do nothing for the virtual device.

WinCUPL's dialog also had QDIF and XNF boxes: cupl writes no QDIF file, and XNF needs an external program (see -zx), so they are left out. Its Device In File and Library settings are Options > Devices and Options > Environment & Tool Paths in LinCUPL, and View Simulation Results is Open LinSim after simulating in the simulator options. There is no box for -q, whose message form the Diagnostics list cannot place on a line, nor for -w and -zq, which do the same as -s and -j.

Settings of earlier LinCUPL versions

Earlier versions labelled the boxes after cupl's usage text. Their settings are converted once: a box is carried over only where its label asked for what its flag did. Gate-Level Equations (which passed -g and so programmed the security fuse), Append Fuse Plot (-d), Create ALL Download Files (-h), the DeMorgan mode that passed -kb, Deactivate unused global OR gates (-z), Warning Messages OFF (-w) and Subtle Warnings OFF (-q) are dropped; their new boxes start at the default, so Secure device is always off after the update. Chip Diagram (-f) becomes Fuse plot, Central Fuse Numbers / PALASM (-c) PALASM source, Truth Table / EDIF (-t) EDIF netlist, IFL File (-i) HL file, and Run CSIM Simulation or Generate Waveform output Simulate after compiling.
