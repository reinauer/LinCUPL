Pins and nodes

PIN

PIN number = [!]name;
PIN [number, number, ...] = [[!]name, name, ...];
PIN [first..last] = [name_first..last];
PIN = [!]name;                        (virtual and fitter devices)

A PIN statement gives a pin of the device a name. The pin numbers are those of the device's package, as decimal numbers. Only pins that the design uses need to be named.

A list assigns several pins at once, the first name to the first number and so on. A range like [14..17] counts up or down; a name range like [q0..3] is short for [q0, q1, q2, q3] and may be written [q0..q3] too:

Pin [2..9] = [a7..0];          /* address bus, a7 on pin 2 */
Pin 1      = !iorq;            /* active-low I/O request */

Pin 12 = !rom_cs;              /* chip selects, active low */
Pin 13 = !ram_cs;
Pin 14 = !io_cs;
Pin 15 = page0;

Pin numbers in a list need not be consecutive:

Pin [4,5,6,8,9,11,12,14] = [d0..7];
Pin [16..21,24,25] = [q0..7];

Assigning one pin twice is an error (pin/node N redeclared), and so is an output equation for a pin that cannot be an output (invalid output pin). The device page explains how to see which pins can do what.

Active-low pins

A ! in front of the name declares the pin active low. The name then stands for the logical signal: it is true when the pin is low. Equations are written in terms of the logical signal and cupl inverts the output (or uses the inverted input) itself. In decoder.pld above, rom_cs is true for addresses 00 to 3F, and the pin 12 goes low then.

The simulator also uses the logical values: a test vector for rom_cs expects H when the chip select is active, which is a low level on the pin.

NODE

NODE [!]name;
NODE [name, name, ...];

A NODE is a buried signal: a macrocell or register whose output does not go to a pin. The compiler or the fitter chooses the node. Nodes are available in the virtual device and in devices that have buried macrocells, like the ATF150x CPLDs:

Node    count_is_zero;                 /* a buried combinational node */

For a device without free nodes (e.g. a GAL22V10) the statement is refused with invalid usage.

PINNODE

PINNODE number = [!]name;
PINNODE [number, ...] = [name, ...];
PINNODE = [name, ...];                 (fitter devices: the fitter chooses)

PINNODE names a buried node by its number. The node numbers of a device come from its data sheet and from the documentation file of a compiled design. Examples are the buried registers of the ATF750 (Device v750c; Pinnode 25 = b;) and the buried macrocells of the ATF150x CPLDs. For a fitter device the number may be left out; the fitter then places the nodes:

Pinnode = [r0..7];                     /* buried registers; the fitter
                                          chooses their macrocells */

Pins without numbers

Pin = name; declares an input or output without a number. The virtual device has no pin numbers at all; for a device placed by a fitter (ATF150x) the fitter chooses the pin, and backpin can write its choice back into the design. A list of zeros, Pin [0,0] = [a, b];, also leaves the numbers to the fitter.

The original reads only one such statement per line and stops with a syntax error at a second Pin = name; on the same line; LinCUPL reads any number of them.

Pin = clk;
Pin = up;
Pin = [d1..0];          /* D flip-flops */

See also: Pin extensions, FIELD, backpin.
