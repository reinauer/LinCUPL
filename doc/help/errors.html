Error messages

cupl and csim report problems as a code in brackets followed by a message. For errors in the source, the line is printed above the message with a ^ under the place where the problem was found:

  3:y = a; y = b;
             ^
[0011ca] expression already assigned to:  y

The four digits number the message; the first letter says which program reported it (c for cupl, s for csim) and the second letter the stage of the run, for example x for the preprocessor, a for the parser and k for the program itself (files, options, the fitter). Messages that start with Please note are notes; the run goes on and the files are written. After an error cupl ends with

Fatal CUPL errors encountered ... program aborted!
Normal exit
Error Code = 1

and exit status 1. The first line reads CUPL errors encountered! when the error came while the fuse map was written, and CSIM errors encountered! when the simulation that -s runs failed. An error of an ATF150x fitter ends the run the same way, after [0010ck] Fitter could not fit design (or [0011ck] Fatal fitter error during processing when the fitter crashed). A successful run ends with Total elapsed time, Error Code = 0 and exit status 0.

The message catalog

Every message has a short explanation and a hint. Open the error message catalog (Help > Error Messages in LinCUPL) to look them up by code or text. The Diagnostics list in LinCUPL shows the explanation of the selected message next to it, and clicking a message moves the cursor to its line.

Frequent messages

MessageUsual cause
invalid syntaxA missing semicolon on the line before, a misspelt keyword, or a reserved word used as a name (out, name, node; see reserved words).
expression already assigned toTwo equations for the same output; use APPEND or combine them.
intermediate var not assigned an expressionA misspelt name, or a pin that was never declared.
unknown extension, invalid usageThe device has no such extension or the pin cannot do this.
invalid output pinAn equation for an input-only pin.
pin/node N redeclaredA pin number used twice.
excessive number of product termsThe output needs more terms than its macrocell has; see Minimization.
multiple unconditional statements for stateTwo OUT statements in one state.
missing header item(s)A header line is missing (a note only).
target device not specifiedNo Device line and no device on the command line.
line exceeds maximum lengthA line longer than 255 characters.
