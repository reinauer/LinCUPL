The simulation listing (.so)

csim -l writes the listing. It starts with the lines of the .si file up to VECTORS, numbered, with the fields of the design inserted where csim learned them. Errors in these lines are shown under the line. Then come the vectors as simulated. This is the listing of counter.si:

=======================
                   c
                   a
      c rp         r
      lesro        r
      kntee  count y
=======================
Reset, then count from 0
0001: 00101  LLLL  L
0002: C1001  LLLH  L
0003: C1001  LLHL  L
0004: C0001  LLHL  L
0005: C1001  LLHH  L
...
Count is 14 now; carry is high at 15
0017: C1001  HHHH  H
0018: C1001  LLLL  L
Preset on the next clock
0019: C0011  HHHH  L
Outputs off
0020: 00000  ZZZZ  L

The names of the ORDER statement are written vertically above their columns, with the blanks of %n. Each vector has its number and one character per signal: the inputs as given, the outputs as simulated (L, H, Z for a disabled output, X for an undefined value). A field shows one character per bit. $MSG texts appear where they were in the file.

Failed vectors

When a simulated output differs from the expected value, csim marks the column with ^ and names each output, with the value that was expected:

0001: C01LLLL
0002: C10LLHL
          ^^^
[0019sa] user expected (H) for c1
[0019sa] user expected (L) for c0
[0019sa] user expected (H) for top

Here the vector expected the count 2 ("2") and top high, but the counter was at 1. The listing shows the simulated values, so the line above the marks tells what the design did. Other messages point at a value that does not fit its column, for example invalid test value for a value that does not suit the signal, such as an input value in single quotes ('5') given to an output field, and excessive test value for a vector with more values than ORDER has signals.

In LinCUPL the messages are also listed under Diagnostics. csim ends with exit status 1 when any vector failed.

Working with the listing

  • Write * for outputs whose value is not known yet, simulate, and check the listing; Assign Simulator Results in LinSim copies the simulated values into the vectors.
  • Mismatches right after reset often come from an active-low pin: the vectors give the logical value, not the pin level.
  • $TRACE shows the register contents around each clock.

The waveform file (.wo)

csim also writes the .wo file with the header, the signals and the simulated vectors. LinSim reads it to draw the waveforms and to merge the simulated values into the vectors it shows.
